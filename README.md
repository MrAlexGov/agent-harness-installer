# agent-harness-installer

CLI-генератор базового **harness** (обвязки) для AI-агента, работающего в репозитории:
контракт-роутер, единственный источник истины по скоупу, ворота верификации, CI —
всё разворачивается одной командой в любой проект.

Реализует методологию курса **Harness Engineering** ([justxor/Harness_ru](https://github.com/justxor/Harness_ru));
этот репозиторий — самостоятельный инструмент-автоматизация поверх неё, а не сам курс.

## Проблема, которую решает

Когда с кодовой базой работает AI-агент (Claude Code, Cursor, Codex и подобные),
без явной обвязки быстро возникает разъезд между тем, что агент считает готовым,
и тем, что реально работает: "зелёные" тесты, которые ничего не проверяют,
контракт-энциклопедия на 500 строк, которую агент не читает целиком, скоуп задачи
в голове агента вместо файла, который можно сверить.

`install.sh` разворачивает минимально достаточную обвязку, которая делает это
невозможным по конструкции, а не по договорённости.

## Ключевые принципы генератора

- **Контракт — роутер, а не энциклопедия.** `AGENTS.md` — короткий, с лимитом строк;
  он указывает, где искать детали, а не пересказывает их.
- **Единственный источник истины по скоупу** — `.agent/feature_list.json`. Не в голове
  агента, не в чате, не в комментарии к коммиту.
- **`passing` ставит только скрипт верификации**, не агент. Агент не может сам
  объявить задачу выполненной.
- **Ворота, которые никогда не падают, — декорация.** Для `generic`-стека генератор
  сознательно оставляет `make test` красным, пока команду не задали явно: красный
  статус честнее фиктивного зелёного.
- **Git — часть обвязки, а не фон.** Без коммитов-чекпоинтов у `verify.sh` нет sha
  для доказательства, а у сессии нет точки отката — поэтому репозиторий по умолчанию
  инициализируется (отключается флагом `--no-git`).
- **Идемпотентность.** Повторный запуск ничего не ломает — существующие файлы либо
  пропускаются, либо перезаписываются с резервной копией (`--force`).

## Что устанавливается

| Файл / каталог | Назначение |
|---|---|
| `AGENTS.md` (+ `CLAUDE.md`) | контракт-роутер: правила работы агента в репозитории |
| `PROGRESS.md` | текущий статус, что сделано, что дальше |
| `DECISIONS.md` | принятые решения и почему — чтобы не переоткрывать заново |
| `BACKLOG.md` | замеченное, но не сделанное — клапан для «заодно» |
| `.agent/feature_list.json` | единственный источник истины по скоупу задач |
| `.agent/clean-state-checklist.md` | чек-лист чистого выхода из рабочей сессии |
| `scripts/verify.sh` | скрипт верификации фичи — только он ставит `passing` |
| `scripts/init.sh` | восстановление контекста в начале сессии |
| `Makefile` | единая точка входа: `make check`, `make test`, `make e2e`, `make arch` |
| `.github/workflows/ci.yml` | CI, прогоняющий те же ворота, что и локально |
| `.claude/` | команды и хуки для Claude Code (профиль `standard`/`full`) |

## Стеки и профили

Автоопределение стека по маркерным файлам — `python` (`pyproject.toml`/`requirements.txt`),
`node` (`package.json`), `go` (`go.mod`), `rust` (`Cargo.toml`), иначе `generic`.
Под каждый стек генератор подставляет реальные команды линтера, тестов, типов и CI.

Три профиля глубины обвязки:

- **`minimal`** — контракт, `PROGRESS.md`/`DECISIONS.md`/`BACKLOG.md`, скоуп,
  `Makefile`, `scripts/verify.sh`. Без CI и без каталога процедур — пакет «за 30 минут».
- **`standard`** (рекомендуется) — `minimal` + `.agent/`, `.claude/` (команды и хуки),
  `docs/`, CI.
- **`full`** — `standard` + рубрика оценщика, sprint contract, документ качества,
  журнал лабораторных, `program.md`/`graph.md`, золотой набор задач.

## Использование

```bash
bash install.sh                                   # текущий проект, профиль standard
bash install.sh -d ~/work/api -s python -p full
bash install.sh --profile minimal --dry-run        # показать, что будет создано
bash install.sh --check                            # проверить уже установленный harness
```

Полный список опций — `bash install.sh --help`.

## Реализация

Один POSIX-совместимый bash-скрипт (~2400 строк), без внешних зависимостей кроме
`bash 4+` и `coreutils`; `jq` и `python3` используются опционально там, где есть —
для работы с `feature_list.json` без хрупкого парсинга JSON в чистом bash.
Скрипт идемпотентен и поддерживает `--dry-run` для предпросмотра любых изменений
перед тем, как что-то писать на диск.
